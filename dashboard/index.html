Bouncer · evidence ledger

What we have measured, and what we have not.

An action firewall for AI agents, checked at three evidence tiers that this page never blends. Everything below is read from the committed result files.

Evidence tiers

  1. Aend-to-end (headline tier)Whole episodes, scored on outcomes. The only tier a headline claim may rest on.
  2. Bper-call diagnostic — not end-to-end evidenceOne action, one verdict, scored against a label. Finds weak spots; proves nothing end-to-end.
  3. Coriginal run — labels leaked into the prompt; archived, do not citeKept only so the correction is auditable. Not plotted, not in any headline.

Tier A end-to-end (headline tier)

Did the attack succeed, and did the real task still finish?

Whole multi-step episodes, scored on outcomes: was the attacker’s objective achieved, and was the legitimate task completed. This is the tier the headline claim has to rest on.

Scope. Systems run end-to-end on this page: deterministic, bouncer-super, bouncer-text-super, nemotron-super, no-defense, text-rules. Read the baselines carefully: deterministic decides from curator labels (data_class, source, destructive, operation_in_goal) that a real deployment would have to detect and that the model is never shown, so its score is an upper bound for rules, not a fair competitor. text-rules sees only the goal, the action text, earlier tool results and the typed destination; no-defense allows everything.

  • This set is small: 12 episodes = 6 attack/benign pairs, one pair per attack family.
  • The deterministic, bouncer-super, nemotron-super baseline already scores perfectly on this set (6/6 attacker objectives prevented, 6/6 benign tasks completed), so the set cannot separate systems yet.
  • This is not proof that Bouncer beats anything. It shows the pipeline runs end-to-end and the scoring is auditable; the comparative claim still needs a harder, larger set and the runs listed under “Not yet shown”.
